run-ledger

Records what an experiment run was, so a difference in results can be attributed — or shown to be unattributable.

A run's identity (commit, config, data, seed, params) is hashed into a fingerprint; its outcome is not. Which makes one situation detectable: same fingerprint + different metrics = something real is going unrecorded.

    Every endpoint, request and response schema, rendered from openapi.yaml.

  • Worked example: does this experiment reproduce? →

    A notebook that records the same experiment three times, finds the metric spread, and reads the verdict back. Executed on every deploy, so what you see actually ran.

  • Python client reference →

    Run.start() to record; runs() and spread() to read back.
Source and design decisions on GitHub. The notebook and client reference on this site are generated at deploy time, never committed — so nothing here can claim a result that was not re-verified.
